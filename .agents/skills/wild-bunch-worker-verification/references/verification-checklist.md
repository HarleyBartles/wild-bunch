# Verification Checklist

- Passing tests do not prove issue-goal conformance.
- Compare the changed source against the issue brief and falsify likely misses.
- Report every validation command that ran and what it returned.
- Include branch, commit SHA, PR URL or number, and a concise touched-files summary.
- If browser or UI work is part of the change, include screenshot evidence or explain why it was unavailable.
- Never claim landed mainline state until the merge has been verified.
