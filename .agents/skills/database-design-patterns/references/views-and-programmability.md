# Views and programmability

Use this reference when creating views, stored procedures, functions, or
triggers. Use views to simplify queries and hide complexity; use procedures and
functions to encapsulate reusable logic; use triggers only when constraints
cannot express the rule.

The authority is the BCcampus textbook chapters on views, stored procedures,
functions, and triggers. Adapt the feature descriptions into usage guidelines.
Warn against overusing triggers and against putting business logic that belongs
in the application into the database.
