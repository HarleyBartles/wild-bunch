# Keys and constraints

Use this reference when choosing primary keys, foreign keys, unique
constraints, check constraints, or domains. Prefer stable, minimal, and
non-null identifiers for primary keys; use constraints to protect data
integrity without duplicating application logic.

The authority is the BCcampus textbook chapters on data integrity and keys.
Adapt the key and constraint guidance into decision rules. Cover surrogate vs
natural keys and when check constraints belong in the database.
