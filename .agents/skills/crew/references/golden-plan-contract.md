# Golden plan contract

The Crew prepare work for golden-gate falsification. Golden does not mean every role said `green`. Golden means every role produced a consumable proof chain, the accepted plan is causally connected to that chain, and downstream busters can falsify the claim without reconstructing hidden reasoning.

## Required chain

A golden-ready plan has:

- Index: known terrain and starting posture.
- Silk: route/goal terrain with traps and reachability marked.
- Writ: lawful and conditionally lawful route proof.
- Klause: one selected start, Goal A, and Plan A, or a named upstream return.
- Rollback: resilience posture attached to Plan A.
- Receipt: integrity check and durable preservation when lawful.

## Workflow boundary

Golden-plan proof prepares a plan for the proper downstream owner; it does not replace that owner.

- Linear/Codex workflow owns normal coding dispatch and worker state.
- The skill stack owns GPT-native skill creation, validation, packaging, and handoff.
- GitHub Operations owns PR, commit, branch, status, merge, and main proof.
- Validation Selection owns validation-class choice once a changed surface or validation claim exists.
- Legacy dispatch skills own only compact Plan B worker packets.

A plan is not golden if it reaches the right result through the wrong workflow surface.

## Proof causality

For a claimed GREEN, the observed proof must be causally derivable from the stated starting state, route, authority, artifact form, and closeout goal. If the claimed result can only be reached by hidden state, a different route, a wrong surface, stale evidence, or a work-shaped substitute, the claim is not golden.

## False-green traps

Crew work should reject:

- a component exists, but the user/work route does not reach it;
- a worker says browser proof, but committed code cannot produce it from the stated clicks;
- tests pass, but issue-goal conformance is unproven;
- a package exists, but installable handoff evidence is missing;
- a route is legal-looking, but Writ has not proven authority/form;
- a plan is singular only because alternatives were never inspected;
- a durable receipt records an unresolved route as if it were settled;
- output shape implies execution or continuity authority that the content does not have;
- Codex Cloud is delegated for GPT-native installed-skill/admin work whose editable source is not proven repo-backed and worker-accessible.

## Composition with busters

`crew-buster` applies this doctrine to a task and returns a planning result.

`boring-buster` may use Crew proof to decide whether a target is predictable enough for its lane.

The current dispatch gate may use Crew proof only for legacy Plan B packet proof after the Linear/Codex route is unavailable, unsuitable, or explicitly rejected.

Specialist skills still own their own law. Crew doctrine describes planning roles and handoff proof; it does not replace dispatch contracts, issue closure gates, validation selection, reporting hygiene, GitHub operations, Linear/Codex state checks, or skill packaging evidence.
