# Unslop playbook

## When

Read this playbook before repository investigation, design, planning, implementation, or review, and again when work crosses into another concern. It is the central procedure for selecting Wild Bunch's unslop profiles and maintaining their observations.

## Select applicable profiles

1. Use the [profile catalogue](../unslop/README.md#profiles) to identify the concerns touched by the task.
2. Read each applicable profile in full before acting and follow its direct route to relevant observations. An index, heading scan, remembered summary, or installed skill does not replace reading the selected profile.
3. Recheck selection when scope changes; add only profiles that govern the new concern. A profile selection is scoped guidance, not a requirement to load every profile.
4. For review, always include the code-review profile and select the profiles for each changed concern.

## Record and improve

When a concrete failure or near miss reveals a possible recurring pattern, inspect [existing observations](../unslop/observations.md) before adding one. Record a distinct incident with the affected work, durable source or delivery reference, recognition cue, corrective action, and linked guard. State what is known about route availability, actual reading, application, and effect; leave unknowns unknown. Multiple comments on one draft are one incident, not proof of recurrence. Do not record successful reads or test runs as receipts.

Compare distinct incidents across tasks and sessions. Create or revise a guard when recurrence supports a reusable correction, or a concrete near miss exposes a preventable mistake. Keep an isolated unproven suspicion as an observation. Every guard names its applicable scope, false-positive boundary, recognition cues, and corrective behavior. Reuse a relevant profile instead of growing a parallel rule inventory.

When a guard fails, distinguish an absent route, an ineffective correction, and useful guidance that was ignored. Repair the actual failure by routing from the work point, clarifying or narrowing the guard, or examining the decision that bypassed it. At review, compare changed behavior with applicable guards and record distinct incidents or meaningful outcomes; do not infer effectiveness from links or structural checks.

Before adding, moving, consolidating, or retiring a profile, read the [routing profile](../unslop/routing.md). Keep useful observations when a guard is replaced or retired. Existing migrated profiles are retained guidance; undocumented incident history is unknown and must not be invented.

## Boundaries

Gameplay rules remain owned by current source and doctrine; unslop guards help recognize and correct agent mistakes against that authority. Explicit user direction takes precedence. When a profile or guard records a durable repository decision, consult the [decision-record playbook](decision-records.md). Route and select only relevant profiles; do not add structural tests that assert document headings or section presence instead of reader behavior.
