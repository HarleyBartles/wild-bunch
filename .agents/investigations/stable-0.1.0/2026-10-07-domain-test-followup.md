# Domain findings: test dispositions and invariant proof

**Status:** Static follow-up to the [Domain investigation](2026-10-07-domain-layer-investigation.md), covering DN-01 through DN-16 and the user's strict CQRS requirement. Existing assertions, relevant fixture construction and supporting production paths were inspected in the live worktree, with repo-wide coverage searches. This is a targeted reassessment, not a claim to have reread every repository test again. The unrelated-criminal shell was subsequently retired under PG-009-R; ledger-only tests identified below were removed with it. The remaining entries preserve the audit findings that informed that decision.

**Decision boundary:** PG-009-R retired unrelated-criminal gameplay from the stable baseline, and the migration explicitly invalidates pre-alpha playthroughs. The former live loop has no compatibility obligation. Fix tests for retained behavior; no test count, passing snapshot round trip or class named EventSourcing can turn an unfinished feature into a baseline obligation. Existing [Application](2026-10-07-application-test-followup.md) and [Persistence](2026-10-07-persistence-test-followup.md) dispositions remain applicable.

## Invariants and scenario families to protect

### 1. Strict CQRS and one authoritative mutation route

Extend the existing query-read-only family across the retained player and developer query boundaries and actual projection endpoints. Before reads, capture independently observable gameplay facts and event/version state from a populated legal history. Read repeatedly in setup, playable town, interrupted journey, completed-awaiting-ack and archived phases where supported. Assert no gameplay fact changes, no pending event is added, and no repository Store/UoW Commit occurs. At Persistence/API boundaries, compare authoritative stored event payloads/positions and retained state through fresh scopes, not only counters on an in-memory double. Include missing/invalid request paths, which must not repair gameplay state or write events as a side effect.

Commands must record their legitimate state effects so event-only reconstruction and the next legal command agree with the live path. Narrow public child mutation seams with production access/caller changes; do not substitute a reflection test that bans every method or force a domain fixture helper into production to preserve existing tests. A command can legitimately return a read DTO after committing; that does not violate CQRS. Infrastructure reconstructing a disposable cache is distinct from a query creating gameplay facts.

Preserve safe player projection tests with populated hidden truth and compare actual serialized API output. Developer audit may retain explicitly internal facts. Existing `BountySaloonEventSourcingTests` property-name restrictions on a subset of events cannot replace that consumer proof, and must not grow into a global ban on hidden state in authoritative domain events.

### 2. Deterministic event-backed lifecycle and next behavior, DN-01/07/13

Strengthen the salt and setup scenario families, not separate tests for each field or dispatcher case. Reconstruct from independent genesis/history without a current-state cache, compare authoritative phase/seed/salt/player facts, and run the same next meaningful command from both states. Repeated replay must not sample entropy, change history, invent health/town facts or create uncommitted events. Include wrong-phase setup operations and the agreed malformed/legacy history policy. Supported old payloads need explicit loader/upcaster behavior; unrecoverable old entropy cannot be fabricated.

For occurrence time, use the existing persisted envelope/audit contract and assert a stored timestamp survives later reads. Removing unused moving-clock getters needs no sleeps or reflection inventory. Keep existing empty-stream/unknown-event/missing-case-history rejection where the history boundary remains valid; do not infer a stronger event-order rule from a misleading test title.

### 3. Reachable saloon confrontation and lawful failure effects, DN-02/08/09

Consolidate normal learn/spot/confront/settle into one coherent Domain scenario with focused declaration variants, one orchestration scenario and the existing persisted HTTP acceptance boundary. Require real spotting to establish whatever eligibility the agreed model needs. Verify surrender/payout once or lawful flee/fine, correct state clearing, replay and safe player output. Retain no-spotted-POI, missing identity and wrong declaration negatives. Do not directly seed presence, confrontation or release progress in a test claiming ordinary feature reachability.

An invalid choice or unaffordable offer rejected before action must leave facts/history unchanged. A failed fight/bribe that legally incurs costs may and must produce authoritative effects. Entering a town action context can legitimately advance time even if a later action fails; do not impose a blanket “every unsuccessful result emits zero events” rule.

If killer release is retained, prove only its agreed counting actions advance it, repeats/unrelated discoveries do not, threshold behavior is reachable and replay preserves it. If deferred or removed, test the actual remaining investigation contract and required absence of the retired feature rather than completing the gate opportunistically.

### 4. Legal travel progression and resource settlement, DN-04/05/06/12/16

Extend existing upkeep/progression and encounter scenarios. Arrange real horse loss on a sufficiently long route, controlled quiet/loss outcomes and independent route-distance/rate expectations. Distance cannot disappear on mode change; delay semantics must stay correct; arrival and acknowledgement must change town/history at their owning events. Available actions must agree with these legal phases. Rejection during a pending encounter or after completion must leave the relevant state unchanged.

For theft, select Food and HorseFeed branches separately while other resources make restoration detectable; assert the recorded theft and actual resource loss agree. Include no-item/alternative-theft behavior if retained. For dust, exercise zero/low reserves after upkeep and earlier same-day effects, asserting the approved legal outcome, actual recorded loss and nonnegative state. Preserve ammunition, water capacity, mounted capability, health and wallet invariants where existing coverage owns them. An exception-free run alone is insufficient if it silently invents resources.

Legacy encounter-profile repair needs a declared supported shape before tests: valid old state must reconstruct deterministically or fail under the agreed policy, and rejected intent must not secretly change gameplay state. NPC interaction and starvation semantics remain scope questions; tests must not invent them from warning copy or generic encounter names.

**Dated disposition, 2026-10-08:** The accepted stable 0.1.0 baseline retires generated interactive friendly trail-NPC encounters and their exclusive tests. Tests for interruption, diary projection and resource tracking now force a real hostile encounter through the event-backed developer override; the generator contract is independently tested against fixed contexts. Starvation semantics are settled in the baseline specification and belong to the retained travel work.

**Follow-up, 2026-10-08:** Removing one weighted category changes fixed-salt outcomes for retained travel events without changing their weights or generator version. Resolver tests now describe the resulting deterministic event, isolate horse/upkeep behavior with a recorded Quiet override, and allow legitimate journey completion when the selected event adds no delay. Generator behavior tests continue to prove that lucky and horse-only events remain selectable.

### 5. Unrelated criminals: retired under PG-009-R, DN-03/10

The ledger unit/wiring/persistence and unrelated-ledger full-replay tests described above were removed with the retired source. Their proposed ledger behavior is not a current test obligation. The migration behavior test owns the selected historical policy by proving pre-alpha session rows and their dependent data are invalidated while schema/migration history remain and a new session can be stored. Retained gang settlement and replay continue to have independent behavior coverage.

### 6. Supported value, content and world boundaries, DN-11/14/15

Keep real duplicate inventory, insufficient cash, charge bounds, horse/saddle, clue/warrant idempotency and service availability negatives. If custom sources are supported, prove their actual action consequences survive storage, not just object equality. If negative bounties/cash or invalid geometry are forbidden, test accepted construction/deserialization boundaries rather than a helper that callers bypass. A concrete accepted input reproducing signed-hash overflow would justify one deterministic index-edge case if those inputs remain supported; do not mutate private hash fields to fabricate reachability.

Removing unused methods, the duplicate generator branch, stale comments or unused occurrence getters generally requires consumer/compile review, not replacement runtime tests. If OnTownReturn is retained as a distinct policy, test its explicitly defined refresh behavior; all current definitions are PerVisit, so a new policy test must follow a decision, not create a feature requirement.

## Consolidation and detectors to retire

The four travel characterization suites repeat the same deterministic fixture across initial state, food, clock, wallet, health, journey completion, logs and diary rows. `TravelResourceTrackingCharacterizationTests` alone has multiple complete journey scenarios and separate fragments of its first advance. Consolidate coherent state transitions and observations while keeping independent failure branches and production persistence/projection boundaries. Do not preserve exact prose, random categories, legacy “six-day” names or arbitrary event totals merely because an old migration captured them. The current foot-only four-day fixture does not itself demonstrate the mounted-to-foot bug.

`TypedDomainEventTests` initializer echoes, interface checks, C# init/record equality inventories and `World/LayoutSaltsTests` constructor/equality tests mostly restate compiler behavior. They do not prove recorded facts are deeply immutable, reconstruct correctly or remain safe at an API boundary. Retire those echoes under the existing test-quality dispositions; preserve genuinely owned envelope/payload compatibility where a real consumer contract exists. `TravelDiarySnapshotShapeTests`, source-string journal guards and dead heat-constant checks should not be rewritten to freeze replacement implementation shapes.

Do not equate fewer tests with stronger proof. Keep small tests for distinct failure behavior, explicit public value contracts and independent adapters; consolidate duplicate setup and repeated assertions of one behavior. Remaining proposed assertions are contingent on an agreed source correction or feature decision. No additional regression is required merely because this audit assigns a finding ID.

**Dated disposition, 2026-10-10:** Plan .65 migrates player action availability to the existing query read model and resolves the completed-journey mismatch. A real six-day quiet journey is advanced through normal commands; while arrival acknowledgement is pending, AdvanceTravelDay is absent, acknowledgement succeeds, and town actions return. Focused behavior tests fail when the completion branch is disabled or when the handler drops the journey snapshot. No separate regression test was added beyond the behavior coverage.
