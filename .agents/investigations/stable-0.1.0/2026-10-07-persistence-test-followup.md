# Persistence findings: test dispositions and replacement behavior

**Status:** Static follow-up to the [Persistence investigation](2026-10-07-persistence-layer-investigation.md), covering PS-01 through PS-17. The unrelated-criminal ledger tests described here were removed under PG-009-R; pre-alpha session invalidation is now the selected history policy and has a migration behavior test. Other entries preserve the original audit findings and proposed dispositions. This is a targeted reassessment, not another claim to have reread every repository test in full.

**Rule:** Change a wrong expectation together with the agreed behavior correction. Strengthen an existing scenario where it already owns the behavior. Add a test only for a genuine gap, not one test per finding or deleted helper. Expected failures must reach the relevant boundary; a green test, method name or identical output cannot prove a branch executed.

Paths below are relative to the repository root. Existing [Application test dispositions](2026-10-07-application-test-followup.md) still apply to shared prep, retry, developer-route and history concerns.

Test paths and conditional recommendations below are a pre-retirement audit snapshot. Ledger-specific paths are historical findings; the selected pre-alpha invalidation behavior is owned by the migration integration test.

## Six cohesive scenario families

These are ownership groups for strengthening the suite, not a target test count. Keep independent negative branches readable and parameterize only when the setup, contract and oracle truly match.

1. **Normal Go preserves generated layout facts (retained layout contract).** Start through the player setup flow, capture the generated town layout and its salts independently, persist `WorldGenerated`, then reconstruct from the event stream and verify those facts. The former developer prep/inject lifecycle and its event codecs are retired; this scenario does not require prepped phases or dev salt mutations.
2. **Derived cache damage cannot rewrite a playthrough (PS-03/04/05/06/08/09/14).** Start with nondefault meaningful state and real command events. Capture semantic expectations before altering caches. Use selected damage cases: stale but valid Player/clock, missing event-established salt/override/history, malformed current JSON and a partially missing multiday diary. Read through aggregate/player/journal with fresh contexts, execute the appropriate next command, and read again. Assert complete semantic facts/order/resources and no invented randomness. Do not treat calling the same projector on both sides as the only oracle. Legitimately absent optional state and invalid event history are separate negative contracts.
3. **Concurrency preserves one legal history (PS-07/10).** Keep the existing two-context same-tail append race; verify exactly the winning action persisted, failed work rolled back, and fresh retry produces one legal additional action. Add the distinct integrity-error negative case. Separately coordinate a writer between read queries and assert a consistent read position. This extends real database behavior rather than reproducing it in the in-memory repository.
4. **Supported history evolves without resets (PS-11/12/16).** Retain public upcaster-chain tests and the real `EfGameSessionRepositoryTests.LegacyWorldGenerated_LoadsFromPersistedEvents_AndCurrentWritesUseV2` (`:31-67`), which already loads persisted v1 history using production upcasters. Extend to event-only repository reconstruction and typed player/journal reads. `GameSessionEventReplayTests.RehydrateFromEvents_Rejects_WorldGenerated_Without_CaseFile_Source` already covers missing case history at Domain; complement it at the persisted loader with missing historical `CaseFileGenerated`, not another equivalent Domain test. Include actual supported previous schema/projection fixtures and writeback-on-next-save. Future/unknown events must fail before any state or save appears. Test immutable stored event rows remain unchanged by upcasting.
5. **Restore the same playable facts through the production seam (PS-13/14).** Consolidate duplicate difficulty/event round trips; move significant whole-session tests to legal command-generated component/repository histories. Preserve codec compatibility for proven legacy trait/warrant/anchor/town shapes. A new explicit restoration factory must reconstruct pending encounter, diary/internal fields, case/town state, stream version and salt so the next command agrees with the command-path state. Compile/caller checks suffice for dead-helper removal.
6. **Schema and release changes preserve their actual contracts (PS-15/16/17).** Keep greenfield schema creation, useful JSONB provider behavior and append/event-ID integrity checks. Add populated supported upgrades and later deployment failure gating where those operations are owned. Remove exact component-count and obsolete source-name detectors where no independent storage consumer requires them. Preserve historical applied migrations even when tests expose prior destructive transitions.

## Fixture and consolidation requirements

- Use fresh DI scopes/DbContexts for post-commit observations. `InMemoryGameSessionRepository` returns stored object references and does not encode/decode JSON, so it remains an Application orchestration double, not a persistence oracle. Do not make it implement EF just to conceal this distinction.
- Reuse production `AddPersistence` or its actual upcaster registration for end-to-end persistence/history proof. Empty registries remain legitimate isolated registry fixtures, but must not silently stand in for the real v2 event writer/reader.
- Replace fixed `[Fact(Skip = ...)]` with the repository's real required PostgreSQL-lane/dependency policy when repairing those scenarios. Setting an environment variable cannot enable a compile-time fixed skip. Keep optional environmental skips explicit; never count skipped paths as proof.
- Strengthen useful existing purchase/journey replay scenarios with selected relevant semantic fields and failure cases. Do not build a reflection-driven generic "compare all properties" framework or a cross-product of every component, phase, API, version and damage type.
- Unknown-event proof belongs at the actual event loader: the existing Domain unknown-event test exercises a different boundary, and `Registry_UnknownTypeWithStoredVersionNot1_Throws` passes version two, which can fail as a future-version error without ever exercising type resolution. Use a current-version unknown type and otherwise-valid known event payload for isolated codec rejection; separately keep future-version rejection on a valid supported payload.
- Synthetic registry transforms are not inherently tautological: public multi-step ordering and construction-time rejection are real library contracts. Consolidate trivial repeats; add duplicate transition and invalid stored-version negatives where missing. Do not discard useful contract tests just because their fixtures are synthetic.
- Verify the corrected scenario would fail against the unfixed behavior for the intended reason. Cache-recovery tests must change/remove cache facts that the assertions observe. A green valid snapshot with only its version edited is not a falsification of the shortcut.

The next implementation plan should bind these scenarios to the accepted source correction and supported historical boundary. No source/test changes or runtime outcomes are claimed by this document.
