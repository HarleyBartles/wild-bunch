fix: persist UnrelatedCriminalLedger in JSON snapshot and PostgreSQL component

The UnrelatedCriminalLedger had ToSnapshot/FromSnapshot methods but they
were never called by the persistence layer. On reload, the ledger was
reconstructed from caseFile.PublicWarrants via BuildUnrelatedCriminalLedger,
which shrinks as warrants are revealed (collected by the player) via
CaseFile.RevealWarrant. This degrades the roster below the 3x redundancy
invariant and loses all active/taken-in/collected/retired state, gang
parity, and next spawn index.

Fix: persist the ledger as a new PostgreSQL component
(unrelatedCriminalLedger) and as a field in GameSessionSnapshot. On load,
the ledger is restored from the snapshot via
GameSessionRehydrator.SetUnrelatedCriminalLedger, overwriting the
constructor's case-file-derived ledger.

Adds JSON snapshot and PostgreSQL round-trip tests verifying that
gang parity, active count, retired IDs, and collected IDs survive
reload after a gang take-in and warrant collection.

Updates MigrationTests and PostgreSqlPersistenceTests component count
assertions (9→10, 10→11) to account for the new component.
