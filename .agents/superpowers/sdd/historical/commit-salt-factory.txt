fix: route ISaltSourceFactory through the setup pipeline for deterministic salt

The ISaltSourceFactory was injected into SeededNewGameFactory but never
used — MysteryTruthResolver called SaltSource.CreateRuntime() directly
for non-Boring entropy modes, producing cryptographically random salt
per invocation. This made integration tests with GameEntropy.Classic
non-deterministic: the ClueSurfacingResolver and WantedPosterResolver
selected different clues/warrants per run depending on the random salt.

Fix: pass ISaltSourceFactory through GameSetupResolver to
MysteryTruthResolver.Resolve. For Boring mode, salt is still
SaltSource.CreateFixed(seedCodeText). For non-Boring modes, the factory
is the single source of truth — RuntimeSaltSourceFactory in production,
DeterministicSaltSourceFactory in integration tests.

Also updates the PostInvestigationActionsUpdateTheJournalAndKeepHiddenTruthPrivate
integration test assertion: with deterministic salt, the boring-mode
ClueSurfacingResolver index (0+1)%2=1 surfaces the second
LocalGossip-tagged clue (Whereabouts kind), not the first. The
assertion now checks for ClueKind.Whereabouts instead of the
description substring "local gossip".
