## Summary

Replaces layout-authored trail topology with geometry-first trail generation that produces clean, connected maps with accurate ride-day labels.

## Problem

BUNCH-123 landed the first visual map/seed-codec/outlier slice, but the trail topology was still too bound to layout-authored trail definitions. The current maps showed quality gaps:
- Ride-day labels diverged from perceived line length
- Some maps produced crossing, closely parallel, or visually redundant trails
- Layouts were doing too much by implying both town placement and trail topology

## Solution

Implemented geometry-first trail generation where:
- Layouts define town placement only
- Trail topology is generated after final town coordinates settle
- Geometry-based edge generation with deterministic entropy/salt selection
- Edge filtering rejects crossings, parallel corridors, and redundant routes
- Ride-day labels derived from final accepted edge lengths

## Implementation

**New components:**
- `TrailGeometry.cs` - Distance calculation, line intersection, parallel detection
- `TrailEdgeGenerator.cs` - Candidate edge generation from pixel-space distances
- `TrailEdgeFilter.cs` - Filtering for crossings, parallel corridors, redundant routes
- `TrailGraphSelector.cs` - Connected graph selection with deterministic entropy
- `RideDayCalculator.cs` - Ride-day distance calculation (2-5 days normal, 6 days outliers)
- `TrailTopologyGenerator.cs` - Main orchestrator coordinating all components

**Integration:**
- Updated `SeedWorldBuilder` to use geometry-first trail generation
- Removed obsolete layout-authored trail generation code from `SeedWorldCatalog` and `SeedWorldMapLayout`
- Updated integration and snapshot tests for new architecture

**Architecture changes:**
- `SeedWorld` no longer pre-generates trails - trails are generated by `SeedWorldBuilder` after town coordinates settle
- `GameSetupDeterministicSource` and `TownNameEntry` changed from `internal` to `public` for test access
