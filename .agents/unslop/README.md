# Unslop in Wild Bunch

Before repository investigation, design, planning, implementation or review, select the applicable profiles below and read them in full. Read their linked observations for known recurrence. Recheck the selection when work crosses a boundary. An index, heading scan, remembered summary or installed skill does not replace the relevant profile.

This directory owns profiles and durable observations under the pinned [unslop subscription](../contracts/operating-standards.json) and [certification](../contracts/standards-certification.md#unslop). Gameplay rules remain owned by current source and doctrine; guards help recognize and correct agent mistakes against that authority. Explicit user direction takes precedence.

If a task fits more than one row, read each relevant profile. Do not impose unrelated guards on untouched concerns. For a general investigation, start with the profiles for the supplied file set and expand only as evidence crosses boundaries.

## Record and improve

When a concrete failure or near miss reveals a possible recurring pattern, inspect [observations](observations.md) before adding a concise distinct incident. Include the affected work, durable source or delivery reference, recognition cue, corrective action and linked guard. Say what is known about route availability, actual reading, application and effect; leave unknowns unknown. Multiple comments on one draft are one incident, not proof of recurrence. Do not record every successful read or test run as a receipt.

Compare distinct incidents across tasks and sessions. Create or revise a guard when recurrence supports a reusable correction, or a concrete near miss exposes a preventable mistake. Keep an isolated unproven suspicion as an observation. Every guard needs applicable scope and a false-positive boundary as well as recognition cues and corrective behavior. Reuse a relevant existing profile instead of growing a parallel rule inventory.

When a guard fails, distinguish an absent route, a correction that did not work and useful guidance that was ignored. Repair the actual failure: route from the work point, clarify or narrow the guard, or examine the decision that bypassed it. At review, compare the changed behavior with the applicable guards, record new distinct incidents or meaningful outcomes, and maintain the certification when adoption surfaces change. Do not infer effectiveness from links or a passing structural check.

Before adding, moving, consolidating or retiring a profile, follow [routing](routing.md). Keep useful observations when a guard is replaced or retired. Existing migrated profiles are retained guidance; their undocumented incident history is unknown and must not be invented. The interactive stable-0.1.0 audit will supply further evidence, not retrospective certification by assumption.
