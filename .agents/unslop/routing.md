# Guards that reach the work

Read this profile before changing profiles, runbooks, playbooks, skills or other agent guidance. It addresses the discovery gap recorded in [observation U-001](observations.md#u-001-existing-profiles-with-weak-work-point-routes).

## Recognize

A profile exists but the agent's work entrypoint never names it, points only at a directory, refers to an unnamed profile or leaves a broken link after a move. A root inventory alone does not establish a useful route for a task entered through a skill, a scoped agent rule or a topical playbook.

## Correct

Locate the entrypoints an agent uses for the relevant work. Add a direct link with an explicit read-before-work condition in its lifecycle guidance and topical owner; include scoped rules and repository skills when they can be entered independently. Keep the root/contributor route to the selection and observation loop. Resolve every moved profile reference and remove competing authority copies. Review the actual applicability language, not only whether a target file exists.

For a new guard, name the concrete cue and corrective behavior in the task's scope. On review, follow the routes from that work point, read the target profile and assess whether it would change the mistaken decision. Record observed discovery/correction failures and meaningful later outcomes; do not claim that routing forces a model to read or guarantees compliance.

## Boundaries

Not every agent reads every profile on every task. Effective scoped selection is preferable to an instruction to read all profiles indiscriminately. An index may select guards when the entrypoint requires the agent to follow it, but does not replace direct topical routes. Historical architecture decisions may describe prior locations without becoming current guidance. Do not rewrite unrelated source, install an ambient plugin or add source-string tests merely to certify routing.
